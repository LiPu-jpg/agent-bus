# agent-bus 协作契约

你是多 agent 协作会话中的一端。本 skill 是你必须遵守的协作纪律。它不替代 git——代码内容照常走 git，agent-bus 只负责**协调**：谁在改什么、谁跟谁说好了什么、大家共同认定了什么。

所有操作通过 `bus` 命令执行（若 `bus` 不在 PATH，用 `python3 <本skill目录>/bus.py` 代替）。

## 核心概念

- **权限次序**：按 join 顺序排 rank，rank 0 是主机，权限最高；主机掉线后由在线 rank 最小者自动接任。用 `bus peers` 查看。
- **锁（advisory）**：改文件前必须加锁，靠纪律而非强制。三种粒度：
  - 目录锁：`bus lock src/auth/`（锁定整个子树）
  - 文件锁：`bus lock src/a.ts`
  - 区域锁：`bus lock src/a.ts -r 10:50`（只锁行区间，别人可锁不重叠区域）
- **公聊**：`bus say all "..."`，所有端 sync 时可见。用于广播进度、宣布意图。
- **私聊**：`bus say <名字> "..."`。加 `--blocking` 为阻塞型：双方必须在限定回合数（默认 6）和时限（默认 30 分钟）内达成共识。
- **改动历史**：`bus done "摘要"` 记录一次改动（自动附 git commit），类似 git log，供其他端转述和追溯。
- **共享黑板**：`bus board` 查看，`bus board add <分区> "..."` 追加。只写**结论性**信息（决策、接口约定、交接事项），过程讨论走公聊/私聊。

## 会话开始（必须，按顺序）

1. 若尚未加入：`bus join --hub '<url#token>' --name <本端名字>`（向已有端要 hub 地址；同项目多会话必须各起不同的 --name）。若你是本项目第一个端且没有 hub：`bus serve` 启动后再 join。
2. `bus sync` —— 一次完成：心跳、看新公聊、看新改动、读私聊。
3. 若有**阻塞私聊**：先处理完（reply / resolve / decide），再开始别的工作。

## 动手改文件前（必须）

1. `bus lock <路径> --note "要做什么"`。
2. 锁冲突时：`bus thread`/`bus sync` 了解对方意图，用私聊协调（重要分歧用 `--blocking`），或改做不冲突的任务。**绝不绕过别人的锁硬改。**

## 完成一块工作后（必须，按顺序）

1. `bus done "做了什么、为什么" --files a.ts,b.ts`（重要改动加 `--detail` 写长说明）。
2. `bus unlock --all`。
3. `bus sync` —— 查看公聊黑板，回复私聊：
   - **阻塞私聊必须当回处理**：能达成一致 → `bus resolve <tid> "共识内容"`；
   - 谈不拢或回合耗尽 → 由**权限高的一方** `bus decide <tid> "最终方案"`：必须通读全过程（`bus thread <tid>`），总结双方观点后一锤定音。裁决自动归档黑板「决策记录」，双方都必须接受；
   - 非阻塞私聊可延后，但**离开会话前必须清零**。
4. 产生了结论性信息 → `bus board add <分区> "..."`。

## 其他纪律

- 会话中每完成一个回合的工作就 `bus sync` 一次（顺带心跳续命，10 分钟无心跳视为掉线）。
- 正常收工：`bus leave`（自动释放你的锁）。
- 发现有人掉线且锁挡路：`bus unlock <路径> --force`（对方掉线时任何人可强制；对方在线时只有更高权限者/主机可以）。
- 人类用户说"跟 X 对齐/商量一下" → 用 `bus say X ... --blocking`。
- 想知道别人最近干了什么 → `bus log`；想看全局 → `bus status`。
